    \section{Objetivo:}

    Mediante la creacion, implementacion de un programa en MicroPython, diseñar el control de 8 leds conectados a una Raspberry Pi Pico, utilizando diferentes secuencias de encendido y apagado, asi como la capacidad de tener la lectura desde la terminal para saber las entradas
    que se estaran realizando para cada secuencia, asi mismo contruir fisicamente el circuito con los leds y las resistencias necesarias para su correcto funcionamiento.
    \section{Desarrollo:}
    
    \subsection{Lógica de Control a Nivel de Bits}
    Para optimizar el manejo de los pines de salida de la Raspberry Pi Pico sin tener que declarar el estado de cada pin de forma individual y repetitiva, se implementó la función \texttt{set\_leds(valor)}, esta función recibe como argumento un número entero el cual representa el estado de los 8 LEDs y se encarga de traducirlo a señales físicas en el microcontrolador.
    
    El funcionamiento de esta parte se basa en operadores de corrimiento a nivel de bits. Dentro de un ciclo \texttt{for} que itera 8 veces, una por cada LED, se aplica la instrucción \texttt{(valor >> i) \& 1}. 
    
    Primero, el operador de corrimiento a la derecha (\texttt{>>}) desplaza los bits del \texttt{valor} ingresado \texttt{i} posiciones hacia la derecha. Esto coloca el bit específico que se desea evaluar en la posición del bit menos significativo. Luego, se aplica la operación lógica AND (\texttt{\&}) con el número 1, esta operación actúa como un filtro para el resto de los bits y separa únicamente el menos significativo, devolviendo como resultado final un 1 lógico (encendido) o un 0 lógico (apagado). Y ya por último, este resultado se envía al método \texttt{.value()} del pin correspondiente.

    \begin{lstlisting}[language={[LAB]Python}, caption={Función para manejar el estado de los pines mediante lógica a nivel de bits}]
def set_leds(valor):
    for i in range(8):
        pines_leds[i].value((valor >> i) & 1)
    \end{lstlisting}

    \subsection{Implementación de un menú de usuario}
    Para facilitar la interacción del usuario con el programa, se hizo la función \texttt{mostrar\_menu()}, con la finalidad de imprimir en la consola de manera estructurada las 8 combinaciones binarias posibles y la acción correspondiente a cada una, mejorando la usabilidad general. Además, esta función se mandará a llamar más tarde y así también mejoramos la legibilidad del código al separar la lógica de presentación de la lógica de control.

def mostrar_menu():

    \subsection{Implementación de Multihilo}
    Uno de los principales retos en el diseño del programa para este sistema de control fue lograr que las secuencias luminosas se ejecutaran de manera ininterrumpida mientras el programa se mantenía a la espera de nuevas instrucciones. En una ejecución secuencial clásica, invocar la función \texttt{input()} que esta es una funcion bloqueante, lo que quiere decir que esta funcion al momento que entra bloquea todos los procesos que se esten ejecutando asi hasta que se vuelva a salir de esto, es por estp que al momento de implementar el multihilo, un hilo se encargara de esta funcion bloqueando mientras el otro hilo seguira ejecutando el programa.

    Para resolver esta parte, implementamos el uso de la biblioteca \texttt{\_thread} nativa de MicroPython, esta biblioteca nos permite crear un hilo de ejecución secundario que opera en paralelo al procesamiento principal del microcontrolador.
    
    La captura de datos se implemento en la función \texttt{leer\_entradas()}, que es la que se ejecuta en el hilo secundario, despliega el menú y entra en un ciclo infinito evaluando la entrada por teclado. Al recibir una cadena, verifica que pertenezca al arreglo de combinaciones válidas (desde \texttt{'000'} hasta \texttt{'111'}) y de ser correcta, actualiza de inmediato la variable global \texttt{Decision}. Al utilizar \texttt{\_thread.start\_new\_thread(leer\_entradas, ())}, el hilo principal queda libre de interrupciones, dedicándose exclusivamente a leer la variable \texttt{Decision} y ejecutar las secuencias de tiempo crítico en el hardware.

    \begin{lstlisting}[language={[LAB]Python}, caption={Interfaz de menú y función de lectura en hilo secundario}]
def leer_entradas():
    global Decision
    Entradas = ['000', '001', '010', '011', '100', '101', '110', '111']
    
    mostrar_menu()
    print(f'\nESTADO INICIAL: [{Decision}] - Todos los LEDs apagados')
    
    while True:
        nueva_opcion = input('\n>> Teclee la combinacion [PIN11, PIN15, PIN17]: ')
        
        if nueva_opcion in Entradas:
            Decision = nueva_opcion
            
            print("\n" + "-"*60)
            if Decision == '000':
                print(f'   Ejecutando: [{Decision}] - Todos los LEDs apagados')
            elif Decision == '001':
                print(f'   Ejecutando: [{Decision}] - Encender / Apagar LEDs')
            elif Decision == '010':
                print(f'   Ejecutando: [{Decision}] - Encender / Apagar Nibbles')
            elif Decision == '011':
                print(f'   Ejecutando: [{Decision}] - Corrimientos entre Nibbles (Derecha)')
            elif Decision == '100':
                print(f'   Ejecutando: [{Decision}] - Corrimientos entre Nibbles (Izquierda)')
            elif Decision == '101':
                print(f'   Ejecutando: [{Decision}] - Corrimientos de LEDs (Derecha)')
            elif Decision == '110':
                print(f'   Ejecutando: [{Decision}] - Corrimientos de LEDs (Izquierda)')
            elif Decision == '111':
                print(f'   Ejecutando: [{Decision}] - Corrimientos de LEDs en Zig-Zag')
            print("-" * 60)
        else:
            print("\n" + "!"*60)
            print("   Opcion no valida.")
            print("   Entradas disponibles: 000, 001, 010, 011, 100, 101, 110, 111")
            print("!"*60)
    \end{lstlisting}


    \subsection{Diseño y Lógica Combinacional de las Secuencias}
    El hilo principal del programa está formado por un ciclo infinito (\texttt{while True}) que evalúa de forma continua la variable global \texttt{Decision}. Dependiendo de su estado lógico, el cual representa las combinaciones binarias desde \texttt{'000'} hasta \texttt{'111'}, el flujo de ejecución se direcciona hacia rutinas específicas. Para optimizar el procesamiento en la Raspberry Pi Pico, estas rutinas se agruparon en tres categorías:
    
    \subsubsection{Secuencias de estado fijo y alternancia de Nibbles (000, 001 y 010)}
    Para los comportamientos más directos, como apagar todos los LEDs (\texttt{000}), generar un parpadeo general (\texttt{001}) o el parpadeo alternado de Nibbles (\texttt{010}), se enviaron directamente literales binarios a la función \texttt{set\_leds}. Por ejemplo, para los Nibbles se alternaron las máscaras \texttt{0b11110000} (parte alta) y \texttt{0b00001111} (parte baja), controlando la frecuencia de oscilación con la instrucción \texttt{time.sleep(0.2)}.

    \subsubsection{Corrimientos direccionales iterativos (011, 100, 101 y 110)}
    Los casos que implican desplazamientos espaciales de LEDs o Nibbles a lo largo de la barra se implementaron utilizando listas que contienen los estados precalculados en formato binario y un ciclo \texttt{for} itera sobre estos arreglos y envía el estado correspondiente.
    
    Un detalle importante en esta implementación es el manejo del control asíncrono, pues dentro de cada iteración del ciclo \texttt{for}, se agregó una validación de estado (\texttt{if Decision != '...': break}). Esto nos garantiza que, si el hilo secundario modifica la variable de control ante un nuevo comando del usuario, el ciclo de corrimiento en curso se interrumpa instantáneamente, logrando un tiempo de respuesta inmediato en el hardware y evitando que la secuencia termine de ejecutarse antes de aplicar el cambio.

    \subsubsection{Implementación matemática del corrimiento en Zig-Zag (111)}
    Para lograr el efecto de rebote de luces tipo Zig-Zag, y no tener que definir una extensa lista de estados de 8 bits, se uso un arreglo que representa únicamente las posiciones espaciales: \texttt{secuencia = [0, 1, 2, 3, 4, 5, 6, 7, 6, 5, 4, 3, 2, 1]}. 
    
    Haciendo uso de un contador global que se incrementa infinitamente (\texttt{paso}) y el operador de módulo (\texttt{\%}), se calcula un índice dinámico pero seguro mediante la expresión \texttt{paso \% len(secuencia)}. Una vez obtenida la posición de la iteración actual, se emplea un operador de corrimiento lógico a la izquierda (\texttt{1 << posicion}) para colocar un único bit en estado alto exactamente en el pin físico que le corresponde.

    Para esto en la ultima que es el Zig-Zag, podemos simular la ejecucion de esta forma viendo como va iterando los pasos por el modulo y el recorrimiento de bits, para esto, tendriamos lo siguiente:

            time.sleep(0.1)

            secuencia = [0b10000000, 0b01000000, 0b00100000, 0b00010000, 0b00001000, 0b00000100, 0b00000010, 0b00000001]

Esta decisión de hardware nos resultó ser mucho más funcional, primero en la implementación en la protoboard y además nos permitió una presentación mucho más limpia visualmente.

    \section{Resultados:}


    Como ya sabemos de la descripción anterior, los LEDs se encienden y apagan de la siguiente manera: el programa utiliza una función principal que actúa como traductor entre un número binario de 8 bits y los pines físicos del microcontrolador. Mediante el uso de operaciones matemáticas a nivel de bits (específicamente desplazamientos y compuertas lógicas AND), el sistema descompone ese número para evaluar cada uno de sus ceros y unos. Dependiendo de este valor, el microcontrolador envía una señal eléctrica en estado alto (1) para encender el LED, o en estado bajo (0) para apagarlo. De esta forma, enviando diferentes patrones binarios, podemos controlar el arreglo de luces a voluntad.

    A continuación, vamos a observar las siguientes opciones de secuencias, de acuerdo a nuestro menú principal:
    \subsection{Caso 1: Leds apagados}

    Esta opción es la más sencilla de todas, ya que simplemente se envía el valor binario \texttt{0b00000000} a la función de control. Esto hace que todos los LEDs se mantengan apagados y que el sistema conserve ese estado de forma continua mientras el programa permanece en esta opción, asegurando que cualquier cambio previo en los LEDs se borre.

     \subsection{Caso 3: Encender / Apagar Nibbles (Parpadear Nibbles)}

    Esta opción hace que los LEDs parpadeen en grupos de 4, es decir, primero se encienden los 4 LEDs de la parte alta (GP7 a GP4) mientras los otros 4 (GP3 a GP0) permanecen apagados, luego se invierte el patrón y se encienden los 4 LEDs de la parte baja mientras los otros 4 se apagan. Para lograr esto, el programa alterna entre enviar el valor binario \texttt{0b11110000} (parte alta encendida) y \texttt{0b00001111} (parte baja encendida) a la función de control, con una pausa de tiempo entre cada cambio de 0.2 {[s]} para que el parpadeo sea visible.

    \subsection{Caso 4: Corrimientos entre Nibbles a la derecha}

Esta opción genera un efecto de desplazamiento visual a la derecha de manera simultánea en ambas mitades del conjunto de LEDs. Para lograr esto, en lugar de utilizar operadores lógicos de corrimiento de bits, el programa itera sobre un arreglo predefinido (\texttt{secuencia}) que contiene los valores binarios \texttt{0b11001100}, \texttt{0b01100110}, \texttt{0b00110011} y \texttt{0b10011001}. De esta forma, dos pares de LEDs (uno en la parte alta y otro en la parte baja) se desplazan una posición a la derecha en cada ciclo. El sistema aplica cada valor del arreglo a los pines correspondientes, haciendo una pausa de 0.2 {[s]} entre cada cambio para que el parpadeo y la ilusión de movimiento sean visibles.

\subsection{Caso 8: Corrimientos de LEDs en Zig-Zag}

Este caso es básicamente la unión de los casos 6 y 7 ya que el Zig-Zag genera un efecto de "rebote" continuo: el punto de luz se desplaza desde el extremo izquierdo (GP0) hacia el extremo derecho (GP7) y al llegar al final, invierte inmediatamente su dirección para regresar hacia la izquierda, creando un movimiento de vaivén que se repite cíclicamente.

Para implementar este caso en lugar de definir una lista de 15 valores binarios precalculados, el programa utiliza una lista que representa únicamente las posiciones espaciales: \texttt{secuencia = [0, 1, 2, 3, 4, 5, 6, 7, 6, 5, 4, 3, 2, 1]}. Un contador global \texttt{paso} se incrementa infinitamente, y mediante el operador de módulo (\texttt{\%}) se calcula un índice dinámico y seguro (\texttt{paso \% len(secuencia)}) y una vez obtenida la posición, se emplea un operador de corrimiento lógico a la izquierda (\texttt{1 << posicion}) para colocar un único bit en estado alto exactamente en el pin físico correspondiente y como en los casos pasados cada cambio de estado tiene una pausa de 0.2 {[}s{]}.

    \section{Conclusiones:}

    \begin{itemize}
        \item \textbf{Espinoza Matamoros Percival Ulises:}
