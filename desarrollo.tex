El punto de entrada \texttt{main.py} lanza dos tareas asíncronas concurrentes mediante \texttt{uasyncio}: \texttt{ble\_central\_task()} para mantener la conexión con el mando, y \texttt{game\_task()} para ejecutar el bucle principal del juego. \subsubsection{Módulo \texttt{main.py}: Control Principal y Conexión}
El archivo main.py se encarga de encender todas las partes del hardware y controlar cómo funciona la aplicación usando tareas simultáneas (programación asíncrona) con uasyncio. Su trabajo principal es preparar los componentes físicos, crear dos tareas que funcionan al mismo tiempo y arrancarlas juntas con asyncio.gather(). Esto asegura que la comunicación por Bluetooth (BLE) y el juego operen en equipo sin estorbarse mutuamente.

\subsubsection{Preparación del Hardware}
La consola prepara la pantalla para que actualice rápido (a 40 MHz) y configura la pequeña bocina (buzzer) en el pin GP15. También crea un objeto llamado \texttt{ControllerState} que funciona como una memoria compartida: la tarea de Bluetooth guarda ahí los datos que recibe del mando, y el juego los lee constantemente sin tener problemas, ya que MicroPython organiza muy bien las tareas.

\begin{lstlisting}[language=Python, caption={Inicialización de hardware SPI y display en la Consola}]
from machine import Pin, SPI
from ili9341 import Display

SPI_ID, PIN_SCK, PIN_MOSI, PIN_MISO = 0, 18, 19, 16
PIN_CS, PIN_DC, PIN_RST, BUZZER_PIN  = 17, 20, 21, 15

spi = SPI(SPI_ID, baudrate=40_000_000, polarity=0, phase=0,
          sck=Pin(PIN_SCK), mosi=Pin(PIN_MOSI), miso=Pin(PIN_MISO))

display = Display(spi,
                  cs=Pin(PIN_CS,  Pin.OUT),
                  dc=Pin(PIN_DC,  Pin.OUT),
                  rst=Pin(PIN_RST, Pin.OUT),
                  width=320, height=240, rotation=270)
display.clear()
\end{lstlisting}

En el mando de juego, se configura la conexión I2C0 de forma rápida (400 kHz) para comunicarse con el sensor de movimiento (MPU-6050) y se preparan los botones aprovechando las conexiones internas del RP2350. Hacer esto rápido evita que leer el sensor haga lento el programa, sobre todo porque esta lectura se hace cada 10 milisegundos.

\begin{lstlisting}[language=Python, caption={Inicialización del bus I2C y los botones en el Mando}]
from machine import Pin, I2C
from imu import MPU6050

# Bus I2C0: SDA=GP8, SCL=GP9, frecuencia 400 kHz (Fast Mode)
i2c = I2C(0, sda=Pin(8), scl=Pin(9), freq=400000)
imu = MPU6050(i2c)

# Pull-up interno: Pin.value() == 0 significa presionado
btn_fire  = Pin(4, Pin.IN, Pin.PULL_UP)
btn_pause = Pin(5, Pin.IN, Pin.PULL_UP)
\end{lstlisting}

\subsubsection{Empaquetado y Envío de Datos por Bluetooth}
Para enviar los datos del control a la consola de forma rápida, se comprimen en un paquete muy pequeño de 10 bytes usando \texttt{struct.pack}. Ahí se guardan dos números con decimales (inclinación X e Y) y dos números enteros (para saber si se apretaron los botones). Hacer esto ocupa muy poco espacio, mucho menos que usar formatos de texto largos. Esta información se manda unas 100 veces por segundo, y además el programa limpia la memoria periódicamente con \texttt{gc.collect()} para que la tarjeta no se trabe tras un rato de uso.

\begin{lstlisting}[language=Python, caption={Lectura del IMU, empaquetado y notificación BLE en el Mando}]
import struct, gc

async def peripheral_task():
    while True:
        connection = await aioble.advertise(
            250_000, name='PicoMando', services=[_SERVICE_UUID]
        )
        while connection.is_connected():
            ax = imu.accel.x   # Inclinacion lateral
            ay = imu.accel.y   # Inclinacion frontal
            fire_pressed  = (btn_fire.value()  == 0)
            pause_pressed = (btn_pause.value() == 0)

            # '<ffbb': 2 float32 (8 bytes) + 2 uint8 (2 bytes) = 10 bytes
            payload = struct.pack('<ffbb', ax, ay,
                                  int(fire_pressed), int(pause_pressed))
            _char.write(payload)
            await _char.notify(connection)

            gc.collect()               # Liberar heap: evita fragmentacion
            await asyncio.sleep_ms(10) # Tasa de envio: 100 Hz
\end{lstlisting}

\subsubsection{Recepción de Datos en la Consola}
La tarea \texttt{ble\_central\_task()} busca el control llamado 'PicoMando' durante 5 segundos. Cuando lo encuentra, se conecta y se queda atenta. Cada vez que llega información, la desempaqueta y actualiza las acciones en el juego. Si por algún motivo se pierde la conexión, el programa espera 2 segundos y se vuelve a conectar solo, sin interrumpir tu partida.

\begin{lstlisting}[language=Python, caption={Tarea BLE de la Consola: escaneo, conexión y deserialización}]
async def ble_central_task():
    while True:
        try:
            async with aioble.scan(5000, interval_us=30000,
                                   window_us=30000, active=True) as scanner:
                async for result in scanner:
                    if result.name() == 'PicoMando':
                        device = result.device
                        break
                else:
                    continue
            connection = await device.connect(timeout_ms=2000)
            service    = await connection.service(_SERVICE_UUID)
            char       = await service.characteristic(_CHAR_UUID)
            await char.subscribe(notify=True)
            while True:
                data = await char.notified()
                # Deserializar: '<ffbb' -> ax, ay, fire, pause
                x, y, fire_val, pause_val = struct.unpack('<ffbb', data)
                ctrl_state.x         = x
                ctrl_state.y         = y
                ctrl_state.fire_raw  = bool(fire_val)
                ctrl_state.pause_raw = bool(pause_val)
        except Exception:
            await asyncio.sleep_ms(2000)  # Reintentar tras desconexion
\end{lstlisting}

\subsection{Módulo \texttt{game.py}: Corazón del Juego}
Este archivo tiene más de 600 líneas porque es la parte principal. Aquí se controla todo: cómo dibujan los gráficos, cómo se mueven los enemigos, los choques entre naves y los menús. La clase \texttt{Game} agrupa todas las piezas físicas (pantalla, botones y sonido) para manejarlas en un solo lugar.

\subsubsection{Preparación y Estado del Juego}
Al empezar, se crean todos los personajes y objetos, además de preparar las reglas: dónde empiezan los enemigos, cuántas vidas tienes, los puntos, el nivel y la dificultad. La función \texttt{setup\_game()} acomoda a los 24 enemigos en sus posiciones iniciales de 3x8 y reinicia el fondo cada vez que empiezas una nueva partida.

\begin{lstlisting}[language=Python, caption={Constructor de la clase Game: instanciación de entidades y estado inicial}]

\subsubsection{Ciclo Principal del Juego}
La función \texttt{run()} es el ciclo infinito que mantiene el juego vivo. Se encarga de mostrar las diferentes pantallas: inicio, puntuaciones, la partida en sí, pausa y "Fin de juego". Cuando estás jugando, la pantalla se actualiza unas 30 veces por segundo. En cada paso mueve al jugador, procesa los disparos, mueve a los enemigos, revisa choques y hace los sonidos. Si logras derrotar a todos, te avanza al siguiente nivel.

\begin{lstlisting}[language=Python, caption={Estructura del bucle principal de juego en run()}]
async def run(self):
    while True:                      # Ciclo externo: reinicia la partida
        self.setup_game()
        await self._splash_screen()      # Pantalla de creditos
        await self._info_screen()        # Tabla de puntuaciones
        self.buzzer.play_start()
        self.display.clear(BLACK)
        self._save_positions()           # Inicializar dirty-rect

        while True:                      # Ciclo interno: partida activa
            self.btn_fire.update_state(self.ctrl_state.fire_raw)
            self.btn_pause.update_state(self.ctrl_state.pause_raw)

            if self.btn_pause.is_pressed():
                await self._pause()      # Menu de pausa

            self._save_positions()       # Guardar para dirty-rect
            self.player.move_analog(-self.ctrl_state.x, -self.ctrl_state.y)

            # Disparar: pulsacion simple o automatico al mantener
            if self.btn_fire.is_pressed():
                self.player_bullets.append(
                    Bullet(self.player.x + PLAYER_W//2, self.player.y, -5, CYAN, HEIGHT))
                self.buzzer.play_shoot()

            self._update_bullets()
            self._collision_detection()
            self._maybe_enemy_shoot()
            self.asteroid.update(self.frame_count, self.asteroid_interval, self.asteroid_speed)
            self.guardian.update(self.frame_count)
            self.dive_bomber.update(self.frame_count, self.dive_bomber_interval,
                                    self.dive_bomber_speed, self.enemies)
            self._move_enemies()
            self._render()               # Renderizado diferencial

            # Limpiar proyectiles inactivos para liberar memoria
            self.player_bullets = [b for b in self.player_bullets if b.active]
            self.enemy_bullets  = [b for b in self.enemy_bullets  if b.active]

            self.buzzer.update()         # Avanzar cola de audio
            self.frame_count += 1

            if self._count_alive() == 0: await self._next_level()
            if self._is_game_over():     break
            await asyncio.sleep_ms(33)   # ~30 fps
\end{lstlisting}

\subsubsection{Dibujado Inteligente de Pantalla}
Para que la pantalla no parpadee ni se ponga lenta, el juego no borra y dibuja toda la pantalla en cada paso. En vez de eso, recuerda dónde estaban los personajes, calcula cuánto se movieron, y solo borra la pequeña estela que dejaron atrás con \texttt{fill\_hrect()}. Esto ahorra mucha memoria y esfuerzo al procesador de la pantalla.

\begin{lstlisting}[language=Python, caption={Renderizado diferencial del jugador: borrado de estela por delta de posición}]
def _render(self):
    fh = self.display.fill_hrect
    fc = self.frame_count

    self._update_and_draw_stars()  # Actualizar fondo en primer plano

    # Calcular desplazamiento del jugador respecto al frame anterior
    dx = self.player.x - self.player._px   # Delta horizontal
    dy = self.player.y - self.player._py   # Delta vertical

    # Borrar solo la estela horizontal expuesta
    if dx > 0:
        fh(self.player._px, self.player._py, dx, PLAYER_H, BLACK)
    elif dx < 0:
        fh(self.player.x + PLAYER_W, self.player._py, -dx, PLAYER_H, BLACK)

    # Borrar solo la estela vertical expuesta
    if dy > 0:
        fh(self.player._px, self.player._py, PLAYER_W, dy, BLACK)
    elif dy < 0:
        fh(self.player._px, self.player.y + PLAYER_H, PLAYER_W, -dy, BLACK)

    self.player.draw(self.display)  # Redibujar sprite en nueva posicion
\end{lstlisting}

\subsubsection{Fondo de Estrellas Movible y Brillante}
El fondo tiene 30 estrellas que caen a diferentes velocidades, lo que da una ilusión de profundidad (como si unas estuvieran más lejos que otras). Para darle un toque realista, usan operaciones matemáticas rápidas para hacer que el brillo de algunas estrellas cambie de repente, haciendo que parezcan titilar sin gastar recursos de la tarjeta.

\begin{lstlisting}[language=Python, caption={Actualización y dibujo del campo de estrellas con titileo aleatorio}]
def _update_and_draw_stars(self):
    dp = self.display.draw_pixel  # Referencia local: 4x mas rapido que global
    for s in self.stars:
        dp(s[0], s[1], BLACK)     # 1. Borrar posicion anterior
        s[1] += s[2]              # 2. Desplazar verticalmente (paralaje)
        if s[1] >= HEIGHT:        # 3. Si sale de pantalla, reiniciar arriba
            s[1] = 0
            s[0] = randint(0, WIDTH - 1)
            s[3] = 8 + (getrandbits(5) % 24)

        # 4. Efecto de titileo: cambio aleatorio de brillo (prob. 1/64)
        if getrandbits(6) == 0:
            flicker = (getrandbits(3) % 7) - 3  # Rango: -3 a +3
            b = max(0, min(s[3] + flicker, 31))  # Clampear 0-31
            s[4] = self._gray565(b * 8)          # Recalcular RGB565

        dp(s[0], s[1], s[4])      # 5. Dibujar en nueva posicion
\end{lstlisting}

\subsubsection{Movimiento de los Enemigos}
El grupo de 24 enemigos se mueve por filas. En vez de mover a todos al mismo tiempo, mueve una sola fila por turno. Conforme vas destruyendo enemigos, el resto se empieza a mover más y más rápido (igual que en los juegos clásicos de maquinita). Si un enemigo toca el borde de la pantalla, todo el grupo baja un poco y empiezan a moverse hacia el lado contrario.

\begin{lstlisting}[language=Python, caption={Movimiento rotativo por filas y descenso al alcanzar el borde}]
def _move_enemies(self):
    total = len(self.enemies)
    alive = self._count_alive()
    # Delay inversamente proporcional a enemigos vivos: la formacion acelera
    delay = max(1, alive * 4 // total)
    if self.frame_count - self.last_enemy_move < delay:
        return
    self.last_enemy_move = self.frame_count

    # Verificar si la fila activa alcanza el borde de la pantalla
    can_move = True
    for e in self.enemies:
        if e.alive and e.row == self.current_row:
            if self.enemy_dir > 0 and e.x + ALIEN_W + self.enemy_speed >= WIDTH:
                can_move = False
            elif self.enemy_dir < 0 and e.x - self.enemy_speed < 0:
                can_move = False

    if not can_move:             # Invertir direccion y descender toda la formacion
        self.enemy_dir *= -1
        for e in self.enemies:
            if e.alive: e.y += ENEMY_DROP   # ENEMY_DROP = 10 pixeles

    for e in self.enemies:       # Mover solo la fila activa
        if e.alive and e.row == self.current_row:
            e.x += self.enemy_dir * self.enemy_speed

    self.current_row = (self.current_row + 1) % NUM_ROWS
\end{lstlisting}

\subsubsection{Choques entre Objetos}
El juego sabe cuando dos cosas chocan al revisar si sus coordenadas se enciman al mismo tiempo. Todo el tiempo revisa si tus disparos le dan a los enemigos, o si los disparos de ellos te dan a ti. Como un detalle extra, hay un enemigo llamado "Guardian" que si chocas con él no te hace daño, sino que te regala una vida extra.

\begin{lstlisting}[language=Python, caption={Detección AABB: proyectiles del jugador contra formación enemiga}]
def _collision_detection(self):
    # 1. Proyectiles del jugador vs formacion de enemigos
    for e in self.enemies:
        for b in self.player_bullets:
            if (b.active and e.alive and
                b.x >= e.x         and b.x <= e.x + ALIEN_W and
                b.y >= e.y         and b.y <= e.y + ALIEN_H):
                e.alive = False
                e.explode()                   # Activar animacion de explosion
                self.total_score += e.score   # 30, 20 o 10 segun fila
                self.buzzer.play_explosion()
                b.active = False

    # 2. Guardian vs jugador: power-up (+1 vida, max 3)
    if (self.guardian.active and
        self.guardian.x >= self.player.x and
        self.guardian.x <= self.player.x + PLAYER_W and
        self.guardian.y >= self.player.y and
        self.guardian.y <= self.player.y + PLAYER_H):
        self.guardian.active = False
        if self.player_lives < 3:
            self.player_lives += 1
        self.buzzer.play_powerup()

    # 3. Proyectiles enemigos vs jugador
    for b in self.enemy_bullets:
        if (b.active and
            b.x >= self.player.x and b.x <= self.player.x + PLAYER_W and
            b.y >= self.player.y and b.y <= self.player.y + PLAYER_H):
            b.active = False
            self.player_lives -= 1
            self.player.explode()
            self.buzzer.play_killed()
\end{lstlisting}

\subsubsection{Disparos Sorpresa de los Enemigos}
Cada cierto tiempo, el juego escoge a un enemigo vivo al azar para que te lance un disparo naranja hacia abajo. Conforme avanzas de nivel, este tiempo de espera se hace más corto, haciendo que tengas que esquivar más cosas.

\begin{lstlisting}[language=Python, caption={Disparo aleatorio de los enemigos de la formación}]
def _maybe_enemy_shoot(self):
    alive = self._count_alive()
    if alive == 0: return
    # Esperar el intervalo de cadencia antes del siguiente disparo
    if self.frame_count - self.last_enemy_shot < self.enemy_rate_of_fire:
        return
    self.last_enemy_shot = self.frame_count

    alive_list = [e for e in self.enemies if e.alive]
    e = alive_list[randint(0, len(alive_list) - 1)]  # Enemigo aleatorio
    # Proyectil desde el centro inferior del sprite del enemigo
    self.enemy_bullets.append(
        Bullet(e.x + ALIEN_W // 2, e.y + ALIEN_H, 4, ORANGE, HEIGHT))
    self.buzzer.play_enemy_shoot()
\end{lstlisting}

\subsubsection{Pantallas y Menús}
El juego maneja cinco pantallas diferentes. Tienes una de créditos y una donde te enseñan cuántos puntos vale cada enemigo. El menú de pausa es bastante interactivo: te puedes mover por las opciones inclinando tu control (leyendo el sensor) e incluso puedes cambiar la dificultad sin tener que reiniciar la partida.

\begin{lstlisting}[language=Python, caption={Menú de pausa: navegación por inclinación del mando}]
async def _pause(self):
    options    = ['Continuar', 'Modo', 'Salir al menu']
    mode_names = ['Facil', 'Normal', 'Dificil']
    selected, last_move_time = 0, 0

    while True:
        now = time.ticks_ms()
        self.btn_fire.update_state(self.ctrl_state.fire_raw)
        fuerza_x = -self.ctrl_state.x  # Eje X del acelerometro

        # Navegar con inclinacion: umbral 0.4g, debounce de 300 ms
        if time.ticks_diff(now, last_move_time) > 300:
            if fuerza_x > 0.4:
                selected = (selected + 1) % len(options)
                last_move_time = now
            elif fuerza_x < -0.4:
                selected = (selected - 1) % len(options)
                last_move_time = now

        if self.btn_fire.is_pressed():
            if   selected == 0: break                      # Continuar
            elif selected == 1:                            # Cambiar dificultad
                self.difficulty_mode = (self.difficulty_mode + 1) % 3
                self._set_difficulty()                     # Aplicar en caliente
            elif selected == 2:                            # Salir al menu
                self.exit_to_menu = True
                break
        await asyncio.sleep_ms(50)
\end{lstlisting}

\subsubsection{Barra de Información}
La pantalla siempre muestra tus puntos y en qué nivel vas en la parte de arriba. Dependiendo del nivel, los colores de los textos cambian para que se vea diferente. Arriba a la derecha aparecen dibujadas tus vidas como pequeñas naves. Para que la pantalla funcione más rápido, esa parte solo se actualiza cuando te quitan una vida.

\begin{lstlisting}[language=Python, caption={Actualización del HUD: puntaje, nivel y vidas}]
def _update_status(self):
    score_text = '{:05d} LVL {:2d}'.format(self.total_score, self.level)
    color = LEVEL_COLOURS[(self.level - 1) % 10]  # Color cambia por nivel
    self.display.draw_text8x8(5, 5, score_text, color, BLACK)

    # Borrar area de vidas solo si el conteo bajo (evita residuos SPI)
    if self.player_lives < self._prev_lives:
        self.display.fill_hrect(WIDTH - 100, 0, 100, 35, BLACK)
    self._prev_lives = self.player_lives

    # Dibujar sprite de nave por cada vida restante (de derecha a izquierda)
    for idx in range(self.player_lives):
        x_pos = WIDTH - ((idx + 1) * (PLAYER_W + 5))
        self.display.draw_sprite(player_sprite, x_pos, 5, PLAYER_W, PLAYER_H)
\end{lstlisting}

\subsection{Módulo \texttt{player.py}: Movimiento del Jugador}
Aquí se maneja la posición y el movimiento de tu nave. Te mueves dependiendo de cómo inclines el control: inclinarlo adelante o atrás te mueve de forma horizontal, y a los lados de forma vertical (solo en la mitad inferior de la pantalla). Hay un pequeño "filtro" del 15\% para ignorar movimientos muy leves, así no te mueves por accidente si te tiembla la mano.

\begin{lstlisting}[language=Python, caption={Movimiento analógico del jugador con zona muerta}]
def move_analog(self, force_x, force_y):
    mov_x = int(force_x * 15)   # Escala: 1g -> 15 pixeles de desplazamiento
    mov_y = int(force_y * 15)

    if abs(force_y) > 0.15:     # Zona muerta del 15%: ignorar deriva
        self.x -= mov_y
        if self.x < 0:                      self.x = 0
        if self.x > self._width - PLAYER_W: self.x = self._width - PLAYER_W

    if abs(force_x) > 0.15:
        self.y -= mov_x
        if self.y < self._width // 2 - 40:  # Limite superior: mitad de pantalla
            self.y = self._width // 2 - 40
        if self.y > 240 - PLAYER_H:         # Limite inferior: borde de pantalla
            self.y = 240 - PLAYER_H
\end{lstlisting}

\subsection{Módulo \texttt{enemy.py}: Animación de los Enemigos}
Este archivo maneja a cada enemigo del juego. Para que parezca que están vivos, alternan entre dos imágenes diferentes muy rápido. Usan un truco matemático muy eficiente para hacerlo sin que el microcontrolador gaste energía de más. También controlan que los enemigos de hasta arriba valgan 30 puntos, y los de más abajo valgan 10, tal como en los juegos viejos.

\begin{lstlisting}[language=Python, caption={Animación de sprite por enmascaramiento de bits y puntuación por fila}]
_ALIEN_PAIRS = ((alien1, alien2), (alien3, alien4), (alien5, alien6))
_SCORES = (30, 20, 10)   # Puntuacion segun fila

class Enemy:
    def __init__(self, start_x, start_y, row):
        self.x     = start_x
        self.y     = start_y
        self.alive = True
        self.row   = row
        self.score = _SCORES[row % 3]
        self.explode_count = 0

    def draw(self, display, frame_count):
        if self.alive:
            pair   = _ALIEN_PAIRS[self.row % 3]
            # frame_count & 0x8: alterna cada 8 frames sin division ni modulo
            sprite = pair[0] if frame_count & 0x8 else pair[1]
            display.draw_sprite(sprite, self.x, self.y, ALIEN_W, ALIEN_H)
        elif self.explode_count:
            explosion = (explode2, explode2, explode1, explode1)
            display.draw_sprite(explosion[self.explode_count - 1],
                                self.x, self.y, EXPLODE_W, EXPLODE_H)
            self.explode_count -= 1
\end{lstlisting}

\subsection{Módulo \texttt{asteroid.py}: Enemigos Especiales}
Aquí se definen tres enemigos extra con formas de moverse muy distintas al resto. El "Asteroid" baja casi en línea recta, el "Guardian" también baja pero es bueno porque te regala vidas, y el "DiveBomber" baja haciendo curvas hacia los lados, lo que lo hace muy difícil de esquivar.

\begin{lstlisting}[language=Python, caption={Trayectoria sinusoidal del DiveBomber}]
import math

def update(self, frame_count, interval, speed, enemies):
    if not self.active and frame_count - self.last_spawn > interval:
        # Escoger un enemigo vivo de la fila 2 como punto de lanzamiento
        row2 = [e for e in enemies if e.alive and e.row == 2]
        if row2:
            e = row2[randint(0, len(row2) - 1)]
            self.x = e.x
            self.y = e.y
            self.active    = True
            self.last_spawn = frame_count

    self.y += speed   # Descender verticalmente
    # Componente X sinusoidal: 3 ciclos completos a lo largo de la altura
    self.x = self._width // 2 + int(
        20 * math.sin(3 * 2 * math.pi * self.y / self._height)
    )
    if self.y > self._height:
        self.active = False
\end{lstlisting}

\subsection{Módulo \texttt{bullet.py}: Disparos}
Esta parte maneja los disparos. Básicamente son iguales para todos, solo que los tuyos son azules y van para arriba, y los de los enemigos son naranjas y van para abajo. El programa los borra en cuanto salen de la pantalla para mantener todo limpio y no saturar la memoria.

\begin{lstlisting}[language=Python, caption={Ciclo de vida del proyectil: movimiento y desactivación por límites}]
class Bullet:
    def __init__(self, x, y, dy, color, height):
        self.x      = x
        self.y      = y
        self.dy     = dy      # Negativo: sube (jugador); Positivo: baja (enemigo)
        self.active = True
        self.color  = color   # CYAN=jugador, ORANGE=enemigo
        self._height = height

    def update(self):
        self.y += self.dy
        # Desactivar al salir de pantalla: el bucle lo eliminara de la lista
        if self.y < 0 or self.y > self._height:
            self.active = False

    def draw(self, display):
        if self.active:
            display.fill_hrect(self.x, self.y, 2, 4, self.color)
\end{lstlisting}

\subsection{Módulo \texttt{buzzer.py}: Sonidos y Música}
Este archivo hace sonar a la pequeña bocina que está conectada. En vez de pausar el juego para que suene algo, funciona como una "fila de espera": puedes decirle que haga varios ruidos seguidos y los va a hacer en orden, uno tras otro. Siempre está configurado para sonar al máximo volumen posible para que se escuche bien claro.

\begin{lstlisting}[language=Python, caption={Método update(): gestión de cola no bloqueante y control de duración}]
def update(self):
    now = time.ticks_ms()
    if self._current is not None:
        freq, dur = self._current
        # Verificar si la nota activa cumplio su duracion
        if time.ticks_diff(now, self._start_time) >= dur:
            self._stop_pwm()
            self._current = None
        return   # Esperar a que termine antes de pasar a la siguiente

    if self._queue:   # Iniciar la siguiente nota de la cola
        self._current    = self._queue.pop(0)
        freq, dur        = self._current
        self._start_time = now
        if freq > 0:
            self._start_pwm(freq)

def _start_pwm(self, freq):
    if self.pwm is not None: self.pwm.deinit()
    self.pwm = PWM(Pin(self.pin_num))
    self.pwm.freq(freq)
    self.pwm.duty_u16(512)  # Ciclo de trabajo del 50%: maximo volumen

# Melodia de muerte del jugador: escala descendente
def play_killed(self):
    for f in [1046, 988, 880, 784, 698, 659, 587]:
        self.tone(f, 80)
\end{lstlisting}

\subsection{Módulo \texttt{virtual\_button.py}: Control de Botones}
Esto es un pequeño filtro que le ayuda al programa a saber exactamente qué quieres hacer con los botones. Puede notar la diferencia entre apretarlo rápido una vez, o dejarlo presionado mucho tiempo (por ejemplo para que la nave dispare de forma automática). Esto es súper útil porque evita tener que poner más componentes físicos y hace que se sienta más natural jugarlo.

\begin{lstlisting}[language=Python, caption={Detección de flanco ascendente y estado mantenido en VirtualButton}]
class VirtualButton:
    def __init__(self):
        self._is_pressed   = False
        self._was_pressed  = False
        self._held_counter = 0

    def update_state(self, is_pressed_bool):
        self._was_pressed  = self._is_pressed
        self._is_pressed   = is_pressed_bool
        if self._is_pressed: self._held_counter += 1
        else:                self._held_counter  = 0

    def is_pressed(self):   # True solo en el frame del flanco ascendente
        event = self._is_pressed and not self._was_pressed
        if event: self._was_pressed = True
        return event

    def is_held(self):      # True si lleva mas de 5 frames presionado
        return self._is_pressed and self._held_counter > 5
\end{lstlisting}

\subsection{Protocolo BLE}
Ambos microcontroladores utilizan el módulo \texttt{aioble} sobre el stack Bluetooth integrado del chip RP2350 de la Pico 2W. El servicio GATT se define con UUIDs de 128 bits personalizados para evitar conflictos con servicios estándar. La característica de datos se configura con permisos de lectura y notificación en el periférico. La Consola realiza un escaneo activo de 5 segundos buscando el nombre de dispositivo \texttt{'PicoMando'}; al encontrarlo, establece la conexión, descubre el servicio y se suscribe a las notificaciones. Ante cualquier desconexión o error, el task BLE espera 2 segundos y reintenta automáticamente, garantizando la reconexión sin intervenir la lógica de juego.
